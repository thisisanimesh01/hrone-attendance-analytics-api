# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | Startup / Lifespan | No indexes created at startup; no unique index on `employees.emp_code` or `attendance_logs.(emp_code, date)`. | Concurrent requests create duplicate records; explain plans show `COLLSCAN`. | Added `@asynccontextmanager` lifespan and `ensure_indexes()` creating unique indexes on `emp_code` and `(emp_code, date)`, plus query indexes for listing and lookups. |
| 2 | `health` (lines 72–74) | Unconditionally returns `{"status": "ok"}` without checking if MongoDB is alive. | Server returns 200 even when database is disconnected or unreachable. | Added `client.admin.command("ping")`; returns 503 if ping fails. |
| 3 | `EmployeeIn` model (lines 53–60) | Missing validation for `emp_code` regex (`^EMP\d{4,6}$`), email format, and rule that `shift_start != shift_end`. | Invalid inputs such as `1001` or identical shifts are accepted with 200 instead of 422. | Built Pydantic v2 `EmployeeCreate` model with regex constraints and `@field_validator` ensuring shift inequality. |
| 4 | `create_employee` (lines 77–85) | Check-then-insert pattern causes race condition under concurrent requests; uses naive `datetime.now()` and returns unformatted date instead of epoch ms. | Concurrent requests with same `emp_code` both insert; response returns string/datetime rather than epoch ms integer. | Rely on MongoDB unique index to raise `DuplicateKeyError` and catch it to return 409; set `created_at` in UTC and serialize to epoch ms. |
| 5 | `list_employees` (lines 88–96) | Off-by-one pagination bug (`skip = page * page_size`); `total` counts whole collection instead of filtered query; lacks sorting by `emp_code` asc. | `GET /employees?page=1` skips the first 20 employees and returns an empty list; `total` ignores `department` filter. | Set `skip = (page - 1) * page_size`; count documents with query `q`; add `.sort("emp_code", ASCENDING)`. |
| 6 | `compute_late_minutes` (lines 33–38) | Ignores timezone, lacks R1 instant truncation to whole seconds, calculates relative to arbitrary naive datetime, and miscalculates grace period boundaries. | Exact grace cutoff (09:40:00 vs 09:40:01) behaves incorrectly; failure with timezone offsets. | Convert to IST timezone-aware datetime; check `diff_seconds > 600`; compute floor whole minutes from scheduled shift start. |
| 7 | `compute_work_hours` (lines 40–42) | Uses Python's default float `round()`, which applies Banker's rounding (round half to even) instead of Rule R4's explicit half-up rounding. | Ties ending in .005 round to even rather than rounding up. | Implemented using `decimal.Decimal` with `ROUND_HALF_UP` quantized to 2 decimal places. |
| 8 | `compute_overtime` (lines 44–48) | Ignores R3 30-minute qualifying threshold (adds overtime even for 5 minutes) and fails across midnight for overnight shifts. | Punch-out with 5 min overtime returns 5 instead of 0; overnight shifts calculate negative or wrong dates. | Enforced >= 30 minute minimum threshold; adjusted scheduled shift end to the next calendar day when `shift_end <= shift_start`. |
| 9 | `punch_in` (lines 99–122) | Does not handle overnight shift attendance dates (R1); leaks internal MongoDB `id` in response; returns BSON datetime instead of epoch ms; relies on check-then-insert. | Punching in at 05:30 for a 22:00-06:00 shift assigns current day instead of previous shift day; concurrent punch-in creates duplicates; API returns illegal `id` field. | Implemented R1 overnight date determination; catch `DuplicateKeyError` to return 409; strip `id`/`_id` and serialize instants to epoch ms. |
| 10 | `list_attendance` (lines 124–150) | In-memory sorting and pagination (`list(db.attendance_logs.find(q))` loads entire collection into memory); does not validate `date_from > date_to` (must return 422); leaks `id`. | Crashes/freezes on ~100k records; invalid date ranges return empty list instead of 422; returns illegal `id` field. | Delegated sorting and pagination to MongoDB using `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(...).limit(...)`; validate `date_from <= date_to`; serialize cleanly. |

## Not a defect

- **`emp_code` generated by client**: We verified that `emp_code` is a customer-supplied business code and not generated by the server. This is by design according to the problem statement and OpenAPI specification.
- **Absence of `ABSENT` / `LEAVE` punch times**: Storing `punch_in: null` and `punch_out: null` for `ABSENT` and `LEAVE` documents is explicitly required by `DATA_MODEL.md`.
